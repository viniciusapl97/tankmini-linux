# 0001 — MVP: preset browser + editor over USB

Status: done — superseded by 0002 (save to flash, names, live edit are solved)
Stack: Rust + GTK4 / libadwaita (decided by default, revisit if the user objects)

## Goal

Replace the official M-EFCS app for the everyday desktop job: see what is on the
pedal, edit a preset, write it back, and keep a local backup. No Bluetooth, no IR
import, no firmware update in this iteration.

## Users / context

Single user (the pedal's owner), Linux desktop (Hyprland/Wayland), pedal attached
by USB-C. The pedal is also the audio interface, so the app must not fight for the
ALSA device it does not need: it only opens the rawmidi node, never the PCM.

## In scope

1. Device discovery: find the pedal by USB VID/PID (`4c4a:c755`) and resolve its
   rawmidi node (`/dev/snd/midiC<card>D<dev>`), falling back to a manual picker.
2. Handshake: `cmd 0x11` identity; show firmware string and refuse unknown devices
   unless the user overrides.
3. Read the active preset block (1942 B) and decode it into an editable model.
4. Show the preset as a chain of effects with their parameters (names and ranges
   come from the decoded block layout, see `docs/protocol/`).
5. Edit parameters locally, with dirty-state tracking; nothing is sent until the
   user applies.
6. Apply: write the block back in 173-byte chunks and verify the read-back.
7. Backup/restore: save/load the raw 1942-byte block to a file with metadata
   (timestamp, firmware string, slot).
8. Slot select (`type 4`, `0xE0000000 + i`) with confirmation.

## Out of scope (this iteration)

- IR / cab upload (`ampCab.bin` format still unknown)
- BLE transport
- Firmware update
- Preset sharing / cloud
- Amp model preview audio

## Requirements

- No root, no udev rule required beyond what the pedal already gets (the rawmidi
  node is group `audio`; the app must explain the fix if it cannot open it).
- The app never sends command `0x21` (ERASE).
- Every write is preceded by an automatic backup of the block being overwritten,
  stored under `~/.local/share/tankmini/backups/`.
- Corruption guard: after a write, read the block back; on mismatch, offer to
  restore the backup immediately.
- Wayland-native window, keyboard-navigable, no Electron/WebView.

## Acceptance tests

1. `tankmini-cli identify` prints `TANK MINI_004` on this unit.
2. `tankmini-cli dump` writes a 1942-byte block equal to
   `tools/mvprobe.py read 4 0 1942`.
3. Editing a parameter and applying changes the read-back byte and, after a
   slot re-select, reverts — proving the pedal reloads from flash (verified
   manually: yes, RAM edits are discarded on re-select).
4. Backup → edit → apply → restore returns the block to the byte-exact original.
5. Unplugging the pedal mid-write leaves the app in an error state, no crash,
   no partial write claimed as success.

## Open protocol questions blocking full implementation

- Meaning of the 21 × 92-byte records inside the block (see
  `docs/protocol/tank-mini-usb-sysex.md` §6).
- Where preset names live (the block has no name field; the pedal shows bank +
  footswitch letters only).
- Whether params need a "refresh" command after a write, like the sibling
  devices do.
- Save-to-flash command (writing the block does not persist across a slot
  re-select, so it is RAM-only today).
